# Habits Tracker — контракт API для backend

Этот файл описывает, какие маршруты должен реализовать backend, чтобы текущий frontend работал полностью. Backend пишешь ты; frontend уже отправляет запросы по этим адресам.

## Общие настройки

- Base URL: `http://127.0.0.1:8000` (указан в `frontend/auth.js` и `frontend/script.js`).
- Все тела запросов и ответы — JSON, кроме ответа `204 No Content`.
- Frontend отправляет запросы с `credentials: "include"`, поэтому авторизация должна работать через cookie.
- `POST /login` должен устанавливать JWT-cookie через `response.set_cookie(...)`. Имя cookie берётся из конфигурации AuthX.
- Не используй Bearer-токен из localStorage: текущий frontend его не отправляет.
- Все защищённые маршруты должны получать пользователя из JWT-cookie. Не принимай `user_id` от клиента.
- Ошибки возвращай в формате `{"detail":"понятное сообщение"}` с подходящим HTTP-статусом.
- CORS: разреши точный адрес Live Server (например, `http://127.0.0.1:5500`) и `allow_credentials=True`. Не используй `allow_origins=["*"]` вместе с credentials.

## Уже используемые маршруты авторизации

### POST /registration

Body:
```json
{"username":"semen","password":"secret"}
```

Frontend ожидает успешный ответ с любым корректным JSON. При ошибке покажет поле `detail`.

### POST /login

Body:
```json
{"username":"semen","password":"secret"}
```

При успехе backend должен установить JWT-cookie. После этого frontend перенаправит пользователя на `index.html`.

## Маршруты, которые нужно реализовать или проверить

### 1. GET /me

Возвращает профиль текущего пользователя, определённого по JWT-cookie.

Response:
```json
{"id":1,"username":"semen"}
```

Если маршрут пока не реализован, frontend временно покажет запасное имя «Мой аккаунт».

### 2. GET /habits

Возвращает привычки текущего пользователя. Важно: каждая привычка должна содержать поле `completed_today` — boolean, отмечена ли она выполненной сегодня.

Response:
```json
{
  "items": [
    {
      "id": 12,
      "name": "Читать",
      "description": "20 страниц",
      "category": "Обучение",
      "icon": "📚",
      "completed_today": true
    },
    {
      "id": 13,
      "name": "Спорт",
      "description": "",
      "category": "Здоровье",
      "icon": "🏃",
      "completed_today": false
    }
  ]
}
```

Можно вернуть и обычный массив объектов — frontend поддерживает оба варианта. Но поле `completed_today` обязательно, иначе отметка не будет отображаться после перезагрузки страницы.

### 3. POST /habits

Создаёт привычку текущего пользователя.

Body:
```json
{
  "name": "Читать",
  "description": "20 страниц",
  "category": "Обучение",
  "icon": "📚"
}
```

Frontend использует поля `name`, `description`, `category`, `icon`.

### 4. PATCH /habits/{habit_id}

Изменяет привычку. Frontend отправляет все четыре поля из POST /habits, а не только изменённые.

Body: такая же структура, как у POST /habits.

Проверяй, что привычка принадлежит пользователю из JWT-cookie.

### 5. POST /habits/{habit_id}/toggle

Переключает выполнение конкретной привычки за сегодняшний день:
- если отметки за сегодня нет — создаёт её;
- если отметка уже есть — удаляет её.

В URL передаётся только `habit_id`. `user_id` нужно получить из JWT-cookie, не объявлять обязательным query-параметром.

Frontend после успешного запроса заново вызывает GET /habits, поэтому ответ может быть, например:
```json
{"ok":true,"completed_today":true}
```

### 6. DELETE /habits/{habit_id}

Удаляет привычку текущего пользователя. Проверяй принадлежность привычки пользователю. Можно вернуть HTTP 204 или JSON с сообщением об успехе.

### 7. GET /time-entries

Возвращает записи рабочего времени текущего пользователя. Новые записи желательно отдавать первыми.

Response:
```json
{
  "items": [
    {
      "id": 44,
      "task_name": "Backend",
      "minutes": 50,
      "source": "pomodoro",
      "created_at": "2026-11-16T16:00:00"
    }
  ]
}
```

### 8. POST /time-entries

Добавляет запись рабочего времени.

Body:
```json
{"task_name":"Backend","minutes":50,"source":"pomodoro"}
```

Для ручного добавления frontend передаёт `source: "manual"`. Проверяй, что `minutes` — целое число от 1 до 1440. Время отдыха не отправляется и не учитывается.

## Важные правила для таблицы выполнений

Таблица выполнений должна позволять:
- одной привычке иметь много записей — по одной на разные даты;
- разным привычкам иметь записи за одну и ту же дату;
- не создавать две отметки одной и той же привычки за один день.

То есть уникальность нужна для пары `habit_id + completed_on`, а не отдельно для каждого из этих полей.

## Проверка после реализации backend

1. Зарегистрироваться и войти.
2. Убедиться, что login устанавливает cookie.
3. Открыть главную страницу: GET /me и GET /habits должны отработать.
4. Создать привычку, изменить её и удалить.
5. Нажать «Отметить»: запись должна появиться в таблице выполнений.
6. Нажать ещё раз: сегодняшняя запись должна исчезнуть.
7. Отметить две разные привычки в один день — обе должны остаться отмеченными.
8. Обновить страницу: состояние отметок должно сохраниться.
9. Добавить время вручную и завершить Pomodoro: записи должны появиться через GET /time-entries.
10. Проверить, что другой пользователь не видит чужие привычки и записи времени.
